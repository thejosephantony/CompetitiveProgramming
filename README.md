## 📖 Introdução

A **Programação Competitiva** é uma prática de resolução de problemas computacionais que exige raciocínio lógico, domínio de algoritmos, análise de complexidade e implementação eficiente.

Diferentemente de apenas escrever um programa que funcione, na programação competitiva é necessário criar soluções que sejam:

- **Corretas**, para todos os casos possíveis;
- **Eficientes**, respeitando limites de tempo e memória;
- **Bem estruturadas**, facilitando a implementação e a depuração;
- **Matematicamente fundamentadas**, quando o problema exige modelagem formal;
- **Rápidas de implementar**, especialmente em contextos de competição.

Esse tipo de prática fortalece a base em Ciência da Computação e é muito útil em disciplinas como Algoritmos, Estruturas de Dados, Matemática Discreta, Teoria dos Grafos e Análise de Complexidade.

## 🧪 Padrão das Soluções

Sempre que possível, cada solução deve conter:

- Nome ou número do problema;
- Plataforma de origem;
- Link do enunciado;
- Estratégia utilizada;
- Complexidade de tempo;
- Complexidade de memória;
- Código-fonte comentado quando necessário.

Exemplo de cabeçalho:

```cpp
/*
    Problema: Nome do Problema
    Plataforma: Codeforces / Beecrowd / AtCoder
    Link: https://...

    Estratégia:
    - Explicação breve da ideia principal.

    Complexidade:
    - Tempo: O(n log n)
    - Memória: O(n)
*/
```

Esse padrão facilita a revisão e ajuda a transformar o repositório em um material de estudo.

## 🚀 Como Compilar e Executar

### Compilação básica

```bash
g++ arquivo.cpp -o programa
./programa
```

### Compilação recomendada para estudos

```bash
g++ -std=c++17 -Wall -Wextra -O2 arquivo.cpp -o programa
./programa
```

### Compilação com entrada e saída por arquivo

```bash
g++ -std=c++17 -Wall -Wextra -O2 solucao.cpp -o solucao
./solucao < entrada.txt > saida.txt
```

### Exemplo usando WSL/Linux

```bash
cd caminho/do/repositorio
g++ -std=c++17 -O2 beecrowd/iniciante/1001.cpp -o main
./main
```

## 📊 Filosofia de Estudo

A evolução em programação competitiva não depende apenas de resolver muitos problemas, mas de estudar de forma consciente.

O ciclo adotado neste repositório é:

```text
Entender o problema
        ↓
Modelar a solução
        ↓
Analisar a complexidade
        ↓
Implementar
        ↓
Testar casos simples
        ↓
Testar casos extremos
        ↓
Corrigir erros
        ↓
Revisar e registrar aprendizado
```

Princípios importantes:

- Não decorar soluções sem entender;
- Sempre analisar a complexidade;
- Revisar problemas difíceis depois de alguns dias;
- Comparar diferentes abordagens;
- Criar templates apenas depois de entender o algoritmo;
- Valorizar código limpo e legível;
- Aprender com erros de submissão.
